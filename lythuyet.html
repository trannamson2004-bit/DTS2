1
Giải thích sự khác biệt giữa position: absolute và position: relative trong CSS. Đưa ví dụ tình huống sử dụng từng loại để tạo layout responsive, và thảo luận về cách chúng ảnh hưởng đến việc deploy website lên hosting (tương thích với các thiết bị khác nhau).

1.1. Khái niệm và sự khác biệt cốt lõi

position: relative định vị phần tử so với chính vị trí ban đầu của nó trong luồng tài liệu (normal flow). Phần tử vẫn chiếm giữ không gian gốc, các phần tử xung quanh không bị dịch chuyển. Thuộc tính top/right/bottom/left sẽ dịch chuyển phần tử lệch đi so với chỗ đứng cũ.

position: absolute lấy phần tử ra khỏi luồng tài liệu — nó không còn chiếm không gian, các phần tử khác sẽ lấp đầy chỗ trống. Vị trí của nó được tính so với phần tử tổ tiên gần nhất có position khác static; nếu không có tổ tiên nào như vậy, nó sẽ định vị so với khung nhìn (viewport) hay phần tử <html>.

1.2. Ví dụ ứng dụng vào layout responsive

Mẫu kết hợp chuẩn: dùng relative cho khung chứa (cha) và absolute cho các yếu tố con bên trong. Khi khung cha co giãn theo màn hình, các yếu tố con luôn bám đúng vị trí tương đối.

/* Khung cha — tạo gốc tham chiếu */
.banner {
  position: relative;
  width: 100%;
  max-width: 1200px;
  margin: 0 auto;
}
/* Tiêu đề con — luôn căn giữa khung cha */
.banner h2 {
  position: absolute;
  top: 50%; left: 50%;
  transform: translate(-50%, -50%);
  color: white;
}
/* Nhãn khuyến mãi — góc trên phải của thẻ sản phẩm */
.product-card { position: relative; width: 30%; min-width: 280px; }
.badge-sale {
  position: absolute;
  top: 10px; right: 10px;
  background: #d97706; color: #fff;
  padding: 4px 10px; border-radius: 6px;
}
Lời khuyên khi làm responsive
Luôn dùng đơn vị tương đối (%, em, rem, vw/vh) thay vì px cứng cho các phần tử absolute, và kết hợp với @media query. Kiểm tra trên nhiều kích thước màn hình bằng DevTools (chế độ Device Toolbar) trước khi đưa lên hosting.

1.3. Ảnh hưởng khi deploy lên hosting & tương thích thiết bị

  • Sai tổ tiên tham chiếu: quên đặt position: relative cho khung cha khiến phần tử absolute trôi ra góc trang — lỗi này chỉ lộ ra khi xem trên màn hình khác kích thước (điện thoại, tablet).
  • Chồng chéo (z-index): các phần tử absolute nằm ngoài luồng nên dễ đè lên nội dung khác; cần quản lý z-index rõ ràng và kiểm tra trên trình duyệt thật (Chrome, Firefox, Safari, Edge) sau khi upload.
  • Khác biệt giữa trình duyệt: một số phiên bản cũ tính toán tọa độ khác nhau; nên chuẩn hóa bằng CSS reset và kiểm tra đa nền tảng trước khi công bố website.
2
Mô tả quy trình đăng ký domain và cấu hình hosting cho một website đơn giản sử dụng JavaScript. Giải thích vai trò của DNS trong quá trình này, và đề xuất ít nhất 2 công cụ hỗ trợ (như GitHub Pages hoặc Netlify) để deploy code mà không cần server riêng. Thảo luận rủi ro bảo mật nếu không cấu hình đúng.

2.1. Quy trình đăng ký domain & cấu hình hosting

  1. Đăng ký tên miền (domain): chọn nhà cung cấp (Namecheap, GoDaddy, Viettel, FPT…), tra cứu tên còn trống, thanh toán và hoàn tất hồ sơ chủ sở hữu miền.
  2. Chọn gói hosting: với website tĩnh HTML/CSS/JS, có thể dùng hosting chia sẻ hoặc các nền tảng tĩnh miễn phí; nhận thông tin máy chủ (FTP, nameserver).
  3. Trỏ domain về hosting: tại trang quản lý domain, điền địa chỉ Nameserver (hoặc bản ghi A/CNAME) do nhà cung cấp hosting cấp.
  4. Upload code: dùng FTP (FileZilla), File Manager của hosting, hoặc Git để đẩy các tệp .html, .css, .js vào thư mục gốc (thường là public_html).
  5. Kiểm tra & bật HTTPS: chờ DNS lan tỏa (vài phút đến 48 giờ), cài chứng chỉ SSL (Let's Encrypt miễn phí) để truy cập an toàn.

2.2. Vai trò của DNS

DNS (Domain Name System — Hệ thống tên miền) hoạt động như một "cuốn sổ điện thoại" của Internet: nó chuyển đổi tên miền dễ nhớ (ví dụ mywebsite.vn) thành địa chỉ IP số học của máy chủ (ví dụ 104.21.x.x). Nhờ DNS, trình duyệt biết phải kết nối đến máy chủ nào để tải về nội dung website. Các bản ghi quan trọng: A (IPv4), AAAA (IPv6), CNAME (bí danh), MX (thư), NS (nameserver).

2.3. Hai công cụ deploy không cần server riêng

  • GitHub Pages: đẩy code lên kho GitHub (công khai hoặc riêng tư với tài khoản Pro), vào Settings → Pages chọn nhánh và thư mục; website được phục vụ tại tentaikhoan.github.io/tenkho, miễn phí và có sẵn HTTPS. Phù hợp trang tĩnh, tài liệu, blog cá nhân.
  • Netlify: kết nối kho Git hoặc kéo-thả (drag & drop) thư mục dự án trực tiếp; tự động build & deploy mỗi khi có commit mới, cấp SSL miễn phí, hỗ trợ tên miền tùy chỉnh và forms. Tích hợp tốt với các framework JavaScript hiện đại.

Công cụ khác có thể tham khảo: Vercel, Cloudflare Pages, Surge.sh.

Rủi ro bảo mật khi cấu hình sai
  • Không bật HTTPS/SSL: dữ liệu truyền đi không mã hóa, dễ bị nghe lén và sửa đổi (MITM); trình duyệt cảnh báo "Không an toàn", làm mất uy tín.
  • Sai bản ghi DNS: domain có thể trỏ nhầm sang trang giả mạo (phishing), hoặc để lộ thông tin hạ tầng nội bộ qua bản ghi không cần thiết.
  • Phân quyền thư mục sai: người ngoài có thể duyệt, đọc hoặc sửa tệp trên server; tệp nhạy cảm (.env, khóa bí mật) có thể bị lộ.
  • Domain hết hạn: mất quyền kiểm soát, kẻ xấu có thể đăng ký lại và mạo danh website để lừa đảo người dùng.
  • Upload nhầm thông tin đăng nhập: đẩy lên Git cả tệp chứa khóa API, mật khẩu — nên dùng .gitignore và biến môi trường.
3
Trong JavaScript, so sánh let, const và var về scope và hoisting. Đưa ví dụ code minh họa một tình huống lỗi thường gặp khi sử dụng sai, và giải thích cách debug bằng công cụ hỗ trợ như Chrome DevTools.

3.2. So sánh về Hoisting (nâng biến)

Cả ba đều được JavaScript "nâng" lên đầu phạm vi trước khi thực thi, nhưng khác nhau ở trạng thái khởi tạo:

  • var: được khởi tạo sẵn với giá trị undefined → gọi trước khi khai báo không báo lỗi nhưng trả về undefined.
  • let / const: được nâng nhưng chưa được khởi tạo — nằm trong "vùng chết tạm thời" (Temporal Dead Zone) → truy cập trước dòng khai báo sẽ ném lỗi ReferenceError.

3.3. Ví dụ lỗi thường gặp & cách sửa

Lỗi kinh điển: dùng var trong vòng lặp kết hợp với hàm bất đồng bộ — tất cả các lần gọi đều dùng chung một biến i đã tăng đến giá trị cuối.

// ❌ SAI — dùng var
for (var i = 1; i <= 3; i++) {
  setTimeout(function() {
    console.log("Lần:", i);
  }, 100);
}
// Kết quả: in ra 3 lần "Lần: 4" (không phải 1, 2, 3)

// ✅ ĐÚNG — thay var bằng let (mỗi vòng lặp có i riêng)
for (let i = 1; i <= 3; i++) {
  setTimeout(function() {
    console.log("Lần:", i);
  }, 100);
}
// Kết quả: 1 → 2 → 3 như mong đợi

// ✅ const dành cho giá trị không đổi
const PI = 3.14;
// PI = 3.1415;  → TypeError: Assignment to constant variable

3.4. Cách debug bằng Chrome DevTools

  1. Nhấn F12 (hoặc Ctrl+Shift+I) → chọn tab Sources, mở tệp .js cần kiểm tra.
  2. Nhấp vào số dòng để đặt breakpoint (dấu chấm xanh) ngay trước đoạn code nghi vấn.
  3. Tải lại trang — thực thi tạm dừng; ở bảng Scope bên phải xem giá trị từng biến (Local, Closure, Global).
  4. Dùng các nút Step over / Step into / Step out để chạy từng dòng, theo dõi biến có bị undefined hay bị ghi đè do dùng sai var.
  5. Tab Console gõ trực tiếp tên biến để kiểm tra giá trị tại thời điểm dừng; tab Network kiểm tra tệp JS có tải về thành công không.
4
Giải thích khái niệm Event Delegation trong JavaScript. Đưa ví dụ ứng dụng trong việc xử lý sự kiện trên danh sách động (dynamic list), và thảo luận lợi ích khi tích hợp với HTML/CSS để tối ưu hiệu suất website.

4.1. Khái niệm Event Delegation (Ủy thác sự kiện)

Event Delegation là kỹ thuật không gắn trình lắng nghe (event listener) cho từng phần tử con, mà chỉ gắn một lần duy nhất cho phần tử tổ tiên chung (cha/ông). Khi sự kiện xảy ra trên một phần tử con, nó sẽ lan ngược (event bubbling) lên tổ tiên; tổ tiên bắt sự kiện, kiểm tra event.target để xác định phần tử gốc rồi xử lý thay.

4.2. Ví dụ: danh sách động thêm/xóa phần tử 

<!-- HTML -->
<ul id="danhSach">
  <li>Mục 1</li>
  <li>Mục 2</li>
</ul>
<button id="nutThem">Thêm mục mới</button>

<script>
const danhSach = document.getElementById('danhSach');

// Chỉ gắn MỘT listener cho cả danh sách (cha)
danhSach.addEventListener('click', function(e) {
  // Kiểm tra đối tượng được nhấp có phải <li> không
  if (e.target.tagName === 'LI') {
    e.target.classList.toggle('da-chon');
    console.log('Đã chọn:', e.target.textContent);
  }
});

// Thêm mục mới SAU KHI chạy — vẫn hoạt động mà không cần gắn lại listener
document.getElementById('nutThem').addEventListener('click', function() {
  const liMoi = document.createElement('li');
  liMoi.textContent = 'Mục mới - ' + (danhSach.children.length + 1);
  danhSach.appendChild(liMoi);
});
</script>

4.3. Lợi ích & tối ưu hiệu suất khi tích hợp HTML/CSS

  • Tiết kiệm bộ nhớ: thay vì hàng trăm listener (mỗi phần tử một cái), chỉ có một listener duy nhất → trang nhẹ hơn, chạy mượt hơn, đặc biệt với danh sách dài.
  • Tự động hỗ trợ phần tử động: các phần tử thêm/xóa sau khi trang tải vẫn được xử lý — không cần gắn/bỏ listener thủ công mỗi lần DOM thay đổi.
  • Code gọn, dễ bảo trì: logic xử lý tập trung một chỗ, dễ sửa đổi và mở rộng.
  • Tích hợp CSS: dùng classList.toggle('da-chon') để chuyển lớp thay vì chỉnh trực tiếp style; CSS quản lý giao diện (.da-chon { color: #297a2e; font-weight: 600; }) giúp nhất quán và dễ thay đổi chủ đề sau này.
  • Tối ưu reflow/repaint: thay đổi lớp CSS thay đổi thuộc tính kiểu được gom nhóm, trình duyệt vẽ lại hiệu quả hơn so với sửa từng style trực tiếp qua JavaScript.
Kết luận
Event Delegation tận dụng cơ chế event bubbling sẵn có của trình duyệt, kết hợp với HTML (cấu trúc danh sách) và CSS (quản lý trạng thái qua lớp) tạo thành mô hình xử lý sự kiện hiệu quả, bền vững và dễ mở rộng — đặc biệt quan trọng với các ứng dụng web hiện đại có nội dung động.
